3. Embeddings

Each chunk becomes a numerical representation capturing semantic meaning.

VECTOR DB
CHUNK_01 → [0.12, -0.44, 0.81, 0.27, ...] CHUNK_02 → [-0.08, 0.66, 0.14, 0.51, ...] CHUNK_03 → [0.73, -0.21, 0.05, -0.38, ...] CHUNK_04 → [0.69, -0.17, 0.09, -0.31, ...] CHUNK_05 → [-0.32, 0.19, 0.72, 0.11, ...] CHUNK_06 → [-0.29, 0.24, 0.68, 0.16, ...]
Embedding model

Converts text into vectors. Similar meanings tend to have nearby vectors.

Vector database

Stores vectors and makes similarity search fast.

Important

The vector itself is not human-readable text. It represents semantic features.

5. Augmented Prompt

This is the key RAG handoff: retrieved context is placed into the LLM's prompt.

CONTEXT + QUERY
SYSTEM: You are a helpful assistant. Answer using the provided context. CONTEXT: [Retrieved chunks will appear here] USER QUERY: [Your query] INSTRUCTION: Use the context to answer the query. If the context does not contain the answer, say you don't have enough information.

6. LLM Generation

The LLM uses the retrieved context to produce a grounded response.

INFERENCE
The generated answer will appear here.
RAG ≠ training

The LLM is not retrained with these documents during this request.

Grounding

The retrieved context gives the model information to reference while answering.

Hallucination risk

Better retrieval and clear instructions can reduce unsupported answers, but don't guarantee zero hallucinations.
